# Передача проекта

Документ для того, кто продолжит работу над Blender Launcher — что где лежит,
почему сделано именно так и обо что легко споткнуться.

Пользовательская документация — в [README.md](README.md), здесь только то,
что нужно разработчику.

## Как собрать и запустить

```bash
./build.sh                 # сборка + упаковка в «Blender Launcher.app» + ad-hoc подпись
./Scripts/build_icon.sh    # пересоздать иконку (нужно только при смене дизайна)
```

Xcode не требуется, хватает Command Line Tools со Swift 5.9+. Проект собирается
через SwiftPM, `.xcodeproj` нет намеренно: приложение маленькое, а SwiftPM
позволяет собирать одной командой из терминала.

Установка свежей сборки поверх текущей:

```bash
pkill -f "Blender Launcher"
rm -rf "/Applications/Blender Launcher.app"
ditto "Blender Launcher.app" "/Applications/Blender Launcher.app"
```

`ditto` вместо `cp -r` — сохраняет структуру бандла и права. После замены
подпись остаётся валидной, проверить: `codesign -v "/Applications/Blender Launcher.app"`.

## Архитектура

Всё состояние живёт в `BlenderManager` — он `ObservableObject` и держит три
вложенных хранилища. Вложенные объекты **не транслируют** свои изменения наверх
автоматически, поэтому в `init()` каждый подписан вручную:

```swift
favorites.objectWillChange
    .sink { [weak self] _ in self?.objectWillChange.send() }
    .store(in: &cancellables)
```

Если добавите ещё одно хранилище — не забудьте такую же подписку, иначе UI
не будет обновляться, а причина совершенно неочевидна.

| Файл | Ответственность |
|---|---|
| `BlenderManager.swift` | Фасад для UI: недавние файлы, автосейвы, запуск процессов |
| `ProjectScanner.swift` | Spotlight-поиск `.blend`, фильтр мусора, обход папок автосейвов |
| `BlenderInstall.swift` | Поиск установок Blender, чтение версий, выбор активной |
| `FavoritesStore.swift` | Избранные проекты |
| `ContentView.swift` | Весь интерфейс |
| `Theme.swift` | Цвета и режимы оформления |

## Решения, которые лучше не ломать

### Запуск второго экземпляра

Ключевая функция приложения. `NSWorkspace.openApplication` и `open -a` уважают
одноэкземплярность: если Blender запущен, система активирует его окно вместо
создания нового. Поэтому запуск идёт напрямую по бинарю внутри бандла:

```swift
process.executableURL = install.binaryURL   // Blender.app/Contents/MacOS/Blender
```

Не заменяйте это на `NSWorkspace` — сломается главное, ради чего написано
приложение. `launchMain()` использует `NSWorkspace` намеренно: это «обычный»
запуск, где переключение на существующее окно и есть ожидаемое поведение.

### Идентификатор файла — путь, а не UUID

`RecentFile.id` вычисляется из `url.path`. Раньше это был `UUID()`, и при каждом
обновлении списка выделение слетало, а дедупликация не работала. Если вернёте
случайный идентификатор — сломается выделение строк и избранное.

### Поиск проектов идёт через Spotlight

`NSMetadataQuery` по `NSMetadataQueryUserHomeScope`. Рекурсивный обход домашней
папки занимает около 20 секунд против 0.15 у Spotlight, поэтому обхода нет.

Следствие: **Spotlight не индексирует скрытые папки**. Автосейвы в `.autosave`
он не найдёт, и поэтому они ищутся отдельно — только внутри директорий, где уже
известны проекты (из истории Blender и результатов поиска). Это несколько
десятков проверок вместо прохода по всему диску.

### Папка автосейвов бывает двух видов

`.autosave` (скрытая) и `autosave` (обычная) — встречаются обе. Обрабатывать
нужно обе, причём по-разному:

- скрытую Spotlight не видит — её содержимое надо собирать вручную;
- обычную видит, и без фильтра её файлы попадают в список проектов.

Поэтому `isRealProject` отбрасывает пути с `/autosave/` и `/.autosave/`,
а `collectProjectAutosaves` перебирает оба имени. Если убрать одну из половин,
автосейвы либо пропадут из своей панели, либо засорят список проектов.

### Фильтр мусора в результатах поиска

`ProjectScanner.isRealProject` отбрасывает конфиги Blender (`userpref.blend`,
`startup.blend`), содержимое `Library/Application Support/Blender/`, а также пути
с `/addons/`, `/presets/`, `/extensions/`. Последние три — потому что пресеты
аддонов лежат и вне `Library`, например в папке разработки аддона.

### Пропавшие избранные не удаляются

`FavoritesStore.files()` помечает отсутствующий файл через `isMissing` вместо
того, чтобы выбросить из списка. Молчаливое исчезновение проекта из избранного
читается как баг, а зачёркнутая строка с пометкой «Файл не найден» объясняет,
что произошло. Открыть такой файл нельзя — проверки стоят и на двойном клике,
и на кнопке «Открыть».

### Миграция настроек

Ключ `BlenderAppPath` из версии 1.0 переносится в `ActiveBlenderInstall`
(см. `migrateLegacyPathIfNeeded`). Удалять эту миграцию рано — у пользователей
1.0 настройка иначе потеряется.

## Хранилище настроек

Домен `local.blenderlauncher`. Посмотреть текущее состояние:

```bash
defaults read local.blenderlauncher
```

| Ключ | Смысл |
|---|---|
| `FavoriteProjects` | Массив путей к избранным проектам |
| `ActiveBlenderInstall` | Путь к выбранной установке Blender |
| `CustomBlenderPaths` | Установки, добавленные вручную |
| `projectListMode` | Активная вкладка списка: `favorites` / `recent` / `scanned` |
| `appearanceMode` | Тема: `system` / `light` / `dark` |
| `BlenderAppPath` | Устаревший ключ версии 1.0, читается только при миграции |

Для проверки пустых состояний удобно сбрасывать отдельные ключи:

```bash
defaults delete local.blenderlauncher FavoriteProjects
```

## Внешние данные, на которые опирается приложение

Всё это принадлежит Blender, а не нам, и может измениться в новых версиях:

| Что | Где | Формат |
|---|---|---|
| Список недавних файлов | `~/Library/Application Support/Blender/<версия>/config/recent-files.txt` | Пути построчно, свежие сверху |
| Автосейвы (временные) | `$TMPDIR` | `<имя>_<PID>_autosave.blend` |
| Автосейвы (у проекта) | `<папка проекта>/.autosave/` или `autosave/` | `<имя>_<timestamp>.blend` |
| Версия установки | `Blender.app/Contents/Info.plist` | `CFBundleShortVersionString` |

Берётся конфиг самой свежей версии — см. `latestVersionConfigDir()`.

## Проверка изменений

Автотестов нет: приложение почти целиком состоит из работы с файловой системой
и интерфейса, и полезность юнит-тестов здесь невысока. Проверяется руками —
что стоит пройти после правок:

1. «Новое окно» при уже запущенном Blender даёт **второй** процесс:
   `ps aux | grep -c "MacOS/Blender"`.
2. Вкладка «Все» показывает проекты, но **не** автосейвы и не пресеты аддонов.
3. Панель автосейвов содержит файлы из обеих папок — и `.autosave`, и `autosave`.
4. Звезда переключается кликом, <kbd>⌘D</kbd> и через контекстное меню;
   отметка видна во всех трёх вкладках.
5. Избранное, выделение и выбранная вкладка переживают перезапуск.
6. Пропавший избранный файл показан зачёркнутым, «Открыть» недоступна.
7. Обе темы читаемы, крашей нет:
   `ls -t ~/Library/Logs/DiagnosticReports/ | grep -i blenderlauncher`.

Первый запуск после установки вызывает системный запрос доступа к папкам —
без него список найденных проектов будет пустым. Это ожидаемо, не баг.

## Скриншоты для сайта и README

**Не снимайте интерфейс на своих рабочих проектах** — на кадрах видны пути
и названия папок, а репозиторий публичный. Один раз это уже пришлось
переснимать и переписывать историю коммитов.

Порядок: создать папку с нейтральными `.blend` (пустой файл с заголовком
`BLENDER17-01v0502` сойдёт — лаунчер читает только имена и даты), временно
подменить `recent-files.txt`, спрятать реальные папки автосейвов, снять кадры
и **сразу вернуть всё обратно**.

Картинки на сайте вшиты как data URI — страница остаётся одним самодостаточным
файлом. Исходники кадров лежат в `docs/assets/` и используются в README.

## Выпуск версии

1. Поднять `CFBundleShortVersionString` и `CFBundleVersion` в `Resources/Info.plist`.
2. Обновить версию на сайте (`docs/index.html`, блок с характеристиками).
3. `./build.sh`, установить в `/Applications`, проверить по списку выше.
4. Собрать архив и выпустить:

```bash
ditto -c -k --sequesterRsrc --keepParent "Blender Launcher.app" "Blender-Launcher-macOS-arm64.zip"
git tag v1.2.0 && git push origin v1.2.0
gh release create v1.2.0 "Blender-Launcher-macOS-arm64.zip" --title "Blender Launcher v1.2.0" --notes "…"
```

В описании релиза обязательно указывать, что сборка только под Apple Silicon
и что при первом запуске нужен правый клик → «Открыть»: приложение подписано
ad-hoc и не нотаризовано, Gatekeeper его блокирует.

Сайт публикуется через GitHub Pages из ветки `main`, папка `/docs` — отдельных
действий после пуша не требуется.

## Что можно сделать дальше

- Сборка под Intel или universal binary — сейчас только arm64.
- Нотаризация, чтобы убрать пляски с Gatekeeper (нужен платный аккаунт разработчика).
- Ручной порядок избранного перетаскиванием — сейчас сортировка по дате изменения.
- Определение версии Blender по заголовку `.blend` и подбор подходящей установки.
  Заголовок читается (`BLENDER17-01v0502` — это 5.2), но файлы сжаты Zstandard,
  так что понадобится распаковка первого блока. От автоподбора отказались
  сознательно: выбор версии оставлен ручным.
